## 2. Custom First-Principles Engine vs. Borrowed Libraries

To maintain full architectural honesty, DQSE explicitly separates custom-built engine subsystems from reused open-source libraries:

- **Built from first principles in this repository:**
  - Recursive-descent SQL lexer, parser, and JSON-serializable AST (`processing/sql_parser.py`).
  - Logical planner and 5-rule analytical optimizer (`processing/logical_plan.py`): projection pushdown, predicate pushdown, catalog partition pruning, two-phase distributed hash aggregation, and skew-aware salted hash shuffle.
  - Physical multi-stage DAG compiler (`processing/physical_plan.py`).
  - Virtual-node consistent-hashing ring (`processing/consistent_hash.py`) for partition-to-worker cache affinity and deterministic failover lists.
  - Explicit byte-accurate `MemoryPool` and Arrow IPC disk `SpillManager` (`processing/memory_pool.py`), plus spillable hash aggregation and Grace hash join (`processing/operators.py`).
  - Bounded `VersionedLRUCache` with table-snapshot epoch invalidation (`processing/cache.py`).
  - SQLite transactional snapshot/partition/lineage/quarantine catalog (`models/catalog.py`).
  - Distributed Coordinator DAG scheduler with task leases, worker crash eviction, retries, idempotent output commits, and query cancellation (`services/coordinator.py`).
  - Multi-process gRPC Worker server with peer-to-peer Arrow IPC shuffle store (`services/worker_server.py`).
- **Borrowed libraries:**
  - `pyarrow` handles low-level Parquet decoding, row-group statistics reading, Arrow IPC stream framing, and vectorized column kernels.
  - `grpcio` provides HTTP/2 RPC transport.
  - `duckdb` and `datafusion` serve strictly as external single-node reference engines for exact numerical verification and head-to-head latency baselines — never as hidden backends for DQSE query execution.

## 3. Dataset License & Clean-Room Compliance

The benchmark dataset (`orders`, `lineitem`, `customer`, `nation`) is generated by an original clean-room synthetic generator (`ingestion/generator.py`, Apache-2.0). While table and column roles are inspired by standard order-analytics schemas such as TPC-H, **no TPC-H source code, `dbgen` binaries, or TPC data files are included or downloaded**, and **no claim of official audited TPC-H compliance or publishable TPC-H metrics is made**. There are no territorial, commercial, or redistribution restrictions.

## 4. Platform Compatibility & Companion Rust Crate

- **macOS ARM64 (tested host):** Full Python 3.12.8 multi-process distributed engine (Coordinator + N independent gRPC worker processes + DuckDB + DataFusion + Control Tower UI) runs natively without Docker via `./scripts/run_portable.sh`.
- **Linux x86_64 / ARM64 (containerized & CI):** Supported via `infra/docker/Dockerfile.standalone`, `docker-compose.standalone.yml`, multi-profile `docker-compose.yml` (`core`, `analytics`, `observability`, `full`), and GitHub Actions (`ubuntu-24.04`).
- **Companion Rust Worker Crate (`rust_worker/`):** The workstation used for development does not have `rustc`/`cargo` or Docker installed, so the companion Tonic + Arrow + DataFusion Rust crate (`rust_worker/`) and `infra/docker/Dockerfile.rust` (`rust:1.86.0-slim-bookworm`) are provided as container-buildable reference code and explicitly disclosed as uncompiled on this host (see `docs/limitations.md`).
